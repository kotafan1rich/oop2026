# OOP 2026 — пошаговая игра с роботами



## Сборка и запуск

Для сборки необходимы компилятор с поддержкой C++20 и CMake версии 3.20 или
новее.

```bash
cmake -S . -B build
cmake --build build
./build/game
```

## Лабораторная работа № 1

> Базовая игровая механика: роботы, поле, перемещение и игровой цикл.

### Основные требования — 6 баллов

1. **Робот и его характеристики**
   - Реализовать класс робота.
   - Добавить текущее и максимальное здоровье, атаку, текущую и максимальную
     энергию, текущий опыт и опыт, необходимый для повышения ранга.
   - Предусмотреть методы изменения характеристик с контролем допустимых
     значений.
   - При взаимодействии с вражеским роботом наносить урон.
   - При взаимодействии с дружественным роботом восстанавливать определённое
     количество здоровья.
   - Повышать ранг робота после накопления необходимого количества опыта.
   - При повышении ранга увеличивать характеристики робота.

2. **Игровое поле**
   - Реализовать класс клеточного игрового поля.
   - Передавать размеры поля в конструктор и проверять допустимые минимальные и
     максимальные значения.
   - Хранить конфигурацию проходимых и непроходимых клеток.
   - Запретить роботам занимать непроходимые клетки.
   - Для хранения информации о клетке рекомендуется создать отдельный класс.

3. **Перемещение**
   - Реализовать перемещение роботов по игровому полю.
   - Запретить перемещение на непроходимые клетки.
   - При попытке перейти на занятую клетку запускать взаимодействие с роботом,
     который на ней находится.

4. **Игровой цикл**
   - Реализовать пошаговую систему ходов.
   - Сначала позволять игроку выполнить действия своего робота. Игрок управляет
     ровно одним роботом.
   - Затем выполнять действия остальных роботов под управлением компьютера.
   - В конце каждого хода восстанавливать каждому роботу часть энергии.
   - После завершения хода начинать следующий.
   - На этом этапе считать уровень пройденным после уничтожения всех вражеских
     роботов.

5. **Визуализация**
   - Отображать проходимые и непроходимые клетки, робота игрока и вражеских
     роботов.
   - Не связывать классы робота и поля с выводом или способом отрисовки.
   - Собирать данные о текущей игровой ситуации и отображать их в отдельной
     системе визуализации.

### Дополнительные требования — по 2 балла

- [ ] **Скорость и сложность перемещения.** Добавить роботу скорость,
  определяющую доступное за ход расстояние. Добавить клеткам сложность
  прохождения: чем она выше, тем сильнее уменьшается оставшееся расстояние.

- [ ] **Видимость.** Добавить характеристику, определяющую радиус обзора робота.
  Скрывать от игрока содержимое и проходимость клеток вне зоны видимости.
  Однажды обнаруженные непроходимые и замедляющие клетки, а также заводы должны
  оставаться известными и отображаться вне зоны видимости.

- [ ] **Завод роботов.** Создать занимающий область `2 × 2` клетки завод,
  который через заданное в конструкторе количество ходов создаёт рядом с собой
  врага.

## Лабораторная работа № 2

> Способности, статусы, инвентарь и расширенная визуализация.

### Основные требования — 6 баллов

1. **Интерфейс способности**
   - Создать класс-интерфейс способности робота.
   - Интерфейс не должен хранить данные и должен содержать только публичные
     чисто виртуальные методы.

2. **Способности**

   | Способность | Эффект |
   | --- | --- |
   | Удар вокруг | Наносит урон всем роботам в радиусе одной клетки |
   | Дальний удар | Наносит урон одному выбранному роботу в радиусе трёх клеток |
   | Лечение | Восстанавливает фиксированное количество здоровья применившему способность роботу |
   | Телепортация | Перемещает робота на выбранную проходимую и свободную клетку в радиусе пяти клеток |

   Каждая способность расходует энергию. В начале игры игрок выбирает одну
   доступную способность, а каждый вражеский робот случайно получает лечение или
   телепортацию. За ход разрешено применять способности неограниченное количество
   раз, пока у робота хватает энергии.

3. **Повышение ранга**
   - При повышении ранга позволить игроку получить ещё одну способность, если
     доступны не все, или улучшить уже имеющуюся.
   - Улучшения способностей:
     - **удар вокруг** — увеличение радиуса;
     - **дальний удар** — увеличение урона;
     - **лечение** — увеличение восстанавливаемого здоровья;
     - **телепортация** — снижение расхода энергии.

4. **Интерфейс статуса**
   - Создать класс-интерфейс статуса.
   - Добавить роботам методы для хранения и обработки статусов.

5. **Статусы**

   | Статус | Эффект | Повторное наложение |
   | --- | --- | --- |
   | Замедление | Запрещает перемещение на один ход и исчезает в конце хода | Продлевает действие на несколько ходов |
   | Перегрузка | Блокирует следующую попытку применить способность, после чего исчезает | Срабатывает как одна перегрузка |
   | Горение | Наносит урон заданное в конструкторе количество ходов | Увеличивает длительность |
   | Щит | Поглощает фиксированное количество урона; превышение наносится здоровью | Увеличивает объём поглощаемого урона |

6. **Статусы клеток**
   - Позволить клеткам накладывать статусы на наступившего робота.
   - При генерации назначать клетке от нуля до двух статусов. Чем больше статусов
     у клетки, тем ниже должна быть вероятность её появления.
   - После срабатывания удалять с клетки один случайный статус.

### Дополнительные требования — по 2 балла

- [ ] **Дополнительные эффекты способностей:**
  - удар вокруг накладывает перегрузку;
  - дальний удар накладывает горение;
  - лечение накладывает щит, если восстановление превысило максимальное здоровье;
    размер щита равен величине превышения.

- [ ] **Инвентарь игрока.** Добавить предметы, восстанавливающие здоровье и
  энергию, а также временно повышающие атаку. Для их получения реализовать статус,
  который срабатывает только на роботе игрока.

- [ ] **Режимы визуализации.** Добавить стандартный режим, подсветку врагов,
  непроходимых клеток и клеток со статусами. В CLI использовать для подсветки
  разные цвета.

## Лабораторная работа № 3

> Стратегии генерации уровней, сохранения, настройка управления и логирование.

### Основные требования — 6 баллов

1. **Шаблонный класс игры**
   - Реализовать класс, отвечающий за инициализацию, игровой цикл, переход между
     уровнями, победу и поражение.
   - В качестве параметра шаблона принимать класс стратегии генерации уровней и
     количество уровней.

2. **Режимы игры**

   | Режим | Описание |
   | --- | --- |
   | Фиксированные уровни | Уровни считываются из файла и не генерируются |
   | Случайные уровни | Уровни генерируются случайно и постепенно усложняются; их количество фиксируется параметром шаблона |
   | Бесконечный режим | Случайные уровни постепенно усложняются, а игра продолжается до поражения игрока |

   Сложность последующих уровней повышается за счёт более высоких рангов врагов
   и увеличения количества клеток со статусами.

3. **Переход между уровнями**
   - Сохранять ранг робота игрока, способности и их улучшения, опыт и здоровье.
   - Сбрасывать энергию и снимать все статусы.
   - Позволить игроку выйти в меню, начать новую игру или загрузить сохранение.

4. **Ввод команд и визуализация**
   - Сделать системы ввода и визуализации независимыми друг от друга, класса игры
     и игровых сущностей.
   - Преобразовывать нажатия клавиш в игровые команды.
   - Загружать конфигурацию управления из файла.
   - Если в конфигурации назначены не все команды, одна клавиша соответствует
     нескольким командам или одной команде назначено несколько клавиш, применять
     управление по умолчанию и уведомлять пользователя.

5. **Сохранение и загрузка**
   - Реализовать систему отдельно от класса игры.
   - Разрешить сохранение в любой момент, когда игрок может выполнять действия.
   - Разрешить загрузку при запуске и во время игры.
   - Проверять корректность загружаемых данных.
   - При ошибке загрузки оставлять игру в состоянии, предшествовавшем попытке.

### Дополнительные требования — по 2 балла

- [ ] **Выбор сложности.** Сложность влияет на силу врагов и случайно добавляет
  один или несколько модификаторов:
  - одну способность можно применить только один раз за ход;
  - каждый ход к игроку применяется случайный статус;
  - статусы не снимаются при переходе на следующий уровень;
  - способности нельзя улучшать при повышении ранга.

- [ ] **Настраиваемая визуализация.** Через параметр шаблона выбирать стандартную
  визуализацию или вариант, настраиваемый файлом. В файле задаются символы и их
  цвета для отображения сущностей в разных режимах.

- [ ] **Логирование.** Записывать происходящие в программе события с поддержкой
  следующих уровней:

  | Уровень | Примеры событий |
  | --- | --- |
  | Информация о программе | Загрузка, сохранение, начало новой игры, выход в меню |
  | Информация об игре | Ходы, перемещения, способности, повышение ранга, переход на новый уровень |
  | Ошибки программы | Отсутствующий или некорректный файл сохранения |
  | Ошибки в игре | Недопустимое перемещение или цель способности, выход за границы поля |

  Пользователь должен иметь возможность выбрать любую комбинацию уровней, в том
  числе полностью отключить логирование. Параметр шаблона определяет, записывать
  все события в один файл или разделять информацию и ошибки по разным файлам.
